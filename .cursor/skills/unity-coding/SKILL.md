# Unity C# 编码规范与架构

## 何时使用

- 新增或修改 Unity C# 脚本
- 决定新类的归属目录 / 命名空间 / 程序集依赖
- 代码走查（review）时对照项目规范
- 拆分职责、解耦、重构

## 1. 项目布局约定（本仓库）

| 目录 | 程序集 | 职责 |
|------|--------|------|
| `Assets/Scripts/AutoGenerated` | `AutoGenerated` | 自动生成代码，不手改 |
| `Assets/Scripts/Editor_Game` | `Editor_Game` | 仅编辑器，运行时不可引用 |
| `Assets/Scripts/Frame_HotFix` | `Frame_HotFix` | 框架底层（资源管理等） |
| `Assets/Scripts/Game` | `Game` | 游戏主体代码 |
| `Assets/Scripts/HotFix` | `HotFix` | 业务热更代码（`HotFix.asmdef` 引用最全） |

业务模块在 `Assets/Scripts/HotFix/_Gameplay/` 下按 `A<Module>` 分包：
`AAudio / ABall / ACards / AEvents / APlayers / AUI / AWeapons ...` 以及
`Ball / Brick / Level / Player / Stage / Effect` 等实体目录。

**规则**：新业务代码优先放 `HotFix`；编辑器工具放 `Editor_Game`；跨模块依赖只能向下（Game → Frame），HotFix 之间用 asmdef reference 显式声明，禁止反向依赖。

## 2. 编码规范清单

### 命名
- 类型：`PascalCase`，接口加 `I` 前缀（`IMusic`），抽象基类加 `Base`，编辑器工具加 `Editor` 后缀。
- 字段：私有 `_camelCase`，序列化字段 `m_camelCase` 或 `PascalCase`（同一文件内保持一致），公共属性 `PascalCase`。
- 常量：`UPPER_SNAKE`。
- 私有字段加 `[SerializeField]` 时保留 `_`，编辑器显示为下划线开头，需用 `[InspectorName]` 或改名为无下划线。

### 命名空间
- 一律显式写 `namespace`，与目录层级对应（见 `Assets/Scripts/HotFix/_Gameplay/AAudio/IMusic.cs` 使用 `namespace MoreMountains;` 的情况：若模块已有既定根命名空间则沿用，不要混用）。
- 禁止 `using` 全局污染（`using System;` 可以，其它命名空间尽量文件级 `using` 顶部）。

### MonoBehaviour
- `Awake` → 只做自身引用缓存与初始化；`OnEnable` → 订阅事件；`OnDisable` → 退订事件；`Start` → 依赖外部状态的初始化；`OnDestroy` → 释放非 Unity 托管资源。
- **禁止** 在 `Update`/`LateUpdate` 中做：`GetComponent`、`Find`、`new`（除缓存复用）、字符串拼接、`foreach` over List（非必要）、LINQ、装箱。
- 单例用 `Awake` 中赋值 `Instance = this`，`OnDestroy` 置空；不要在 `OnEnable` 里赋值。
- `GetComponent` 缓存为字段，`[RequireComponent]` 只用于硬依赖。

### 纯 C# 类优先
- 逻辑写成普通 class（可测试、可复用），MonoBehaviour 只做胶水层。
- 需要序列化数据用 `[Serializable] class` + `[SerializeField] List<T>`，避免在 ScriptableObject 之外存数据。
- 需要策划配置用 `ScriptableObject`；需要运行时数据用普通 class。

### 事件与回调
- 优先用 C# `event` / `Action<T>`，不用 UnityEvent 作为代码接口（UnityEvent 只用于 Inspector 配置）。
- 订阅与退订必须成对；用 `OnEnable/OnDisable` 或 `Dispose` 保证对称。
- 回调里不要抛异常打断游戏循环；用日志 + 状态位。

### 异步
- 项目已用 UniTask / PrimeTween / DOTween。异步方法用 `UniTask` + `CancellationToken`；动画用 PrimeTween 或 DOTween，**不要**用 `StartCoroutine` 做复杂流程。
- `async void` 仅允许用于事件处理器，且内部必须 try/catch。

### 错误处理
- 断言用 `UnityEngine.Assertions` 或 `Debug.Assert`（仅开发版）。
- 生产环境用 `Debug.LogError` + 提前 return，不要抛异常。

## 3. 架构设计准则

1. **单向依赖**：`HotFix` → `Game` → `Frame_*`，禁止反向与循环。
2. **模块通信**：跨模块优先通过事件总线（`AEvents`）或接口，不直接持有对方具体类型引用。
3. **数据与表现分离**：数据定义放 `ScriptableObject`/配置表（项目已有 `Excels` 目录 + `DataBase` 模块），表现层只读。
4. **对象生命周期管理**：谁创建谁销毁；池化对象必须有 `OnSpawn/OnDespawn` 复位接口。
5. **单点职责**：一个类只做一件事；超过 300 行考虑拆分；超过 800 行必须拆分。
6. **依赖注入**：优先构造函数注入而非 `FindObjectOfType` 全局查找。

## 4. 代码质量检查清单

- [ ] 无 `Debug.Log` 遗留（改用统一日志封装，带模块前缀）
- [ ] 无魔法数字（提取为 `const` 或配置）
- [ ] 公共 API 有 XML 注释（`/// <summary>`）
- [ ] 循环中无 `GetComponent` / `new` / 字符串拼接
- [ ] 事件订阅与退订对称
- [ ] `Update` 中逻辑为空或极简
- [ ] 命名与模块前缀一致（如 `AudioManager` 位于 `AAudio`）
- [ ] 无废弃 API（`FindObjectOfType` → `FindFirstObjectByType` 等，按项目版本确认）

在 review 或重构任务中，按以下格式给出结果：

```
## 问题
- [严重级别] 文件:行 — 问题描述
  建议：具体修改方式
```
严重级别统一使用：`严重` / `一般` / `建议`。
